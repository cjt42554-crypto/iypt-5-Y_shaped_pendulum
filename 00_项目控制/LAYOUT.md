# 仓库布局

```text
README.md
AGENTS.md
00_项目控制/
01_最终理论/
02_模拟程序/
03_项目资料/
90_候选工作区/
├── current/
└── archive/
tools/
.github/workflows/
```

## 目录职责

| 路径 | 职责 |
|---|---|
| `00_项目控制/` | 单一状态源、布局和工作流 |
| `01_最终理论/` | 已接受的理论成熟基线 |
| `02_模拟程序/` | 已接受的程序成熟基线 |
| `03_项目资料/` | 已接受的资料、协议、结果和归档 |
| `90_候选工作区/current/` | 当前候选、管理记录和审查材料 |
| `90_候选工作区/archive/` | 被替代候选的冻结归档 |

`01_最终理论` 的路径名为兼容既有研究资料而保留；其语义是“当前成熟理论基线”，不是不可修改的最终真理。

## 状态单一化

- 动态状态只写入 `STATUS.md`。
- 根 README 只导航，不复制状态值。
- 当前候选 README 只描述候选自身。
- 历史审查和冻结证据保留其生成时路径，不作为当前入口。

## 活动路径约束

- 项目控制入口固定为 `00_项目控制/`。
- 成熟程序入口固定为 `02_模拟程序/`。
- 候选工作区入口固定为 `90_候选工作区/`，活动候选固定为其 `current/` 子目录。
- 历史审查和冻结证据可以保留生成时路径；活动 README、命令和执行入口必须使用上述当前路径。

机器检查由 `tools/check_repository_layout.py` 执行。
