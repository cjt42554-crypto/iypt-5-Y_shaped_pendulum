# 工作目录与接续方式

[当前交接](交接说明_current.md) 是唯一动态状态入口；[工作规范](../AGENTS.md) 是唯一活动管理规范。本文只说明目录职责和使用路径，不维护第二份待办或测试台账。

[Codex 下一阶段工作计划](Codex_下一阶段工作计划.md) 给出本轮接续任务与验收；实施状态只更新 current，原任务单保留既有验收依据。

## 目录职责

| 入口 | 放什么 | 不放什么 |
| --- | --- | --- |
| [01_最终理论](../01_最终理论/README.md) | 当前采用的前向物理、数值方法、结构理论及相关协议 | 按日期复制的平行“最终版” |
| [02_模拟程序](../02_模拟程序/README.md) | 实际维护的源码、配置、测试、界面与技术说明 | 无验证却冒充正式后端的候选副本 |
| [03_研究记录](../03_研究记录/README.md) | 专题推导、审查、数值证据、失败记录和冻结快照 | 当前待办的第二份副本 |
| [04_实验与数据](../04_实验与数据/README.md) | 测量来源、原始/派生数据、标定与留出划分、外部数据索引 | 把合成样例冒充真实测量 |
| [tools](../tools/) 与 `.github/workflows/` | 持续使用的检查器和只读 CI | 遗留的自动改仓库控制器 |

保留 `01_最终理论`、`02_模拟程序` 的现有路径和各语言的包布局，避免破坏脚本与版本引用。“最终”表示当前采用的版本，不表示已经完成数值收敛或实验验证。四个研究层次是物理前向、数值实现、高保真参考、结构性研究；它们不必机械对应四个顶层文件夹。

## 日常工作

开始时阅读 current 的未完成项与验收条件，再按任务读取理论和程序。普通维护直接修改唯一采用版本；只有竞争方案需要探索目录。完成后运行受影响检查，把结果和未完成项写回 current，并提交、推送。

需要沉淀的计算在 `03_研究记录/专题/<主题>/<运行标识>/` 留下配置、源版本、命令、环境、结果与退出原因；维护/审查放在 `03_研究记录/维护/<日期>_<任务>/`。小任务不强制创建新目录，复用已有记录即可。当前没有活动候选，不预建空的 `90_探索工作区/`；独立替代模型出现时再按需创建，写清与正式实现的差异、来源和状态。尚未整理的临时结果可放 `90_探索工作区/_scratch/`，该路径被 Git 忽略，不是证据备份。

已冻结记录保留原始内容；重新计算或修订结论新建有来源关系的记录。原始数据放数据区或可靠外部存储，不只留在会过期的 CI 附件。采用探索成果时更新唯一正式实现，旧候选仅在支撑证据或比较需要时保留，并明确其身份。

## 旧路径与旧规则

旧候选区的 current/history 已移到本目录；旧材料的迁移路径与哈希见 [迁移清单](../03_研究记录/维护/2026-09-05_目录重组/migration.json)。2026-09-06 的重复候选与中间输出清理见 [原精简记录](../03_研究记录/维护/2026-09-06_仓库精简.md)；2026-10-31 的版本选择、必要历史和退役文件见 [内容整理记录](../03_研究记录/维护/2026-10-31_内容整理.md)。旧报告、审批口令和机器配置仅反映其原版本，不作为当前工作权限；其中仍有效的科学限制继续保留在 current 和最小证据中。

冻结结果中的旧路径不批量改写，以免破坏原始字节和校验关系。查仍保留的旧文件位置可运行 `python tools/resolve_legacy_path.py '<旧仓库相对路径>'`；映射目标已精简删除时，按精简记录从 Git 历史恢复。复现历史计算应检出记录所绑定的原 commit，而不是假定历史脚本自动适用于当前源码。未完成事项继续看 current，不从目录名推断研究问题已解决。

`交接说明_history.md` 保持空文件。Git 追溯使用 `git log --follow -- 00_项目管理/交接说明_current.md`；源文件、配置、数据和实际日志优先于摘要。

## 检查入口

在仓库根目录运行：

```bash
python -m unittest discover -s tools -p 'test_repository_docs.py' -v
python tools/check_repository_docs.py
```

求解器安装和回归命令见 [程序入口](../02_模拟程序/README.md)。软件测试、数值收敛、物理标定和留出实验验证分别报告，不用一个 PASS 混为一谈。
