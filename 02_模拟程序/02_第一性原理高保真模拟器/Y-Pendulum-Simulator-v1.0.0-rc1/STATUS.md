# RC1 高保真模拟器状态说明

## 当前状态

`Y-Pendulum-Simulator-v1.0.0-rc1` 作为历史参考与回滚后端冻结。

正式高保真总状态为：

`HF_NUMERICAL_QUALIFICATION_NO_GO`

该状态意味着：

- RC1 不是已经获得空间、时间和连续守卫资格的高保真求解器；
- 单条成功或完成的短轨迹不能代表空间收敛、接触后动力学、装置级物理或实验验证；
- 0.12 s 保存轨迹只能作为来源受限的归档候选工件；
- 历史空间运行的外层源码端点探针存在已记录限制；
- 旧 RC1 结果保持原版本绑定；后续修改不能继承旧版本未获得的数值或实验资格。

## 允许用途

RC1 可继续用于：

1. 复核历史归档工件与来源；
2. 回滚比较和接口兼容性检查；
3. 读取既有配置、输出 schema 与历史数值行为；
4. 在明确标注未资格状态时，为实验设计提供机制假设来源。

这些用途都不能把 RC1 提升为正式数值资格。

## 禁止解释

不得以 RC1 的单条成功轨迹声称：

- 已证明三支杆或索在真实装置中的压缩、失张或接触；
- 已获得空间收敛、连续守卫或接触后动力学资格；
- 已验证锁频、分岔、混沌、长期闭合或制造参数；
- 已与实验一致；
- 已被 HF-v2 无接触静态参考包替换或升级。

## 维护与版本身份

常规诊断、修复和测试按根 AGENTS 在用户任务范围内进行，不再另设“默认只读/逐次授权”的管理门。原 RC1 的历史结果和输入保持其原 commit 绑定；修改方程、接口或功能后更新相关版本/模型说明并重新验证，不能仍以旧证据覆盖新实现。没有模型语义变化的文档或路径修复不需要虚构新模型身份。

程序测试不能替代空间/时间收敛、连续守卫或装置验证。`HF_NUMERICAL_QUALIFICATION_NO_GO` 仍有效；这限制结论，不禁止开展改善它的工作。

## 历史发布工具与桌面入口

当前使用源码、配置和测试时以本目录的 `pyproject.toml`、`src/`、`configs/`、`tests/` 为准。可移植的桌面入口是 `启动Y形摆模拟器.sh` 或安装后的 `ypendulum-desktop`；不随仓库分发指向个人电脑绝对路径的 `.desktop` 文件。

`scripts/build_release.py` 与 `scripts/verify_release.py` 保留为旧完整 ZIP 的构建身份和校验工具。前者所需的旧 `README.md`、`CHANGELOG.md`、`docs/` 和发布报告已不在当前精简树；必须恢复匹配的历史发布树后使用，不能据此声称当前目录可直接构建旧完整发布包。版本一致性回归仍保留它的版本派生检查。

旧 `scripts/run_release_checks.py` 同样要求上述已退役文档，并启动整套仿真检查；它没有活动调用方，已从当前树移除。需要审计原发布流程或个人启动器时，按 [2026-10-31 内容整理记录](../../../03_研究记录/维护/2026-10-31_内容整理.md) 的基线和具体路径恢复。源码、配置、全部回归及版本身份未因这项整理而改变。
