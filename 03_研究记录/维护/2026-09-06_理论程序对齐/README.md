## 证据存储与恢复

轨迹 `.npz` 沿用仓库根 `.gitattributes` 的 Git LFS 规则，其余配置、JSON、CSV、日志、参考脚本与 patch 随 Git 提交保存。原实现提交上传了 80 个 LFS 对象（约 42 MB）。精简后仅保留必要运行子目录；删除工作树文件不会改写历史或移除服务端 LFS 对象。Git 提交中的 LFS 指针记录每个对象的 SHA-256 和字节数，不依赖临时目录或会过期的 CI 附件。

恢复时克隆仓库并切换到对应提交，安装好 Git LFS 后在仓库根目录执行 `git lfs pull`，再读取 `.npz`；未取回对象时，工作树可能只有文本指针，不能将其当成轨迹文件。计算环境与命令见各阶段 JSON；`implementation.patch` 及恢复 patch 用于审计早期执行版本，无需覆盖现有工作树。
