# HF-v2 分阶段实施计划

## 总体策略

HF-v2 与 RC1 并行开发。每一阶段只解决一个层次的问题，并在进入下一阶段前形成可独立否证的门。禁止一次性重写整个程序后再集中调试。

## P0：基线冻结与候选骨架

### 目标

建立可追踪的 RC1 基线和最小候选包，不改变任何物理结果。

### 工作

1. 记录当前 `main`、正式 `hf/model.py`、`hf/solver.py`、`hf/state.py`、`hf/validation.py`、配置模型和公共 API 的 Git blob SHA；
2. 建立 RC1 入口—依赖—输出图，至少覆盖 `api.py → hf.__init__ → model/solver/state/validation`；
3. 记录现有公开结果字段、状态词汇和主要配置字段；
4. 建立 `HF-v2-core` 最小包与测试入口；
5. 建立候选模型身份、单位约定、坐标约定和随机性政策；
6. 为 RC1 选取小型、快速、无接触、始终张紧的表征算例，仅保存输入和关键不变量，不把 RC1 轨迹冻结为绝对真值。

### 禁止

- 修改正式源码；
- 复制 RC1 单体文件；
- 运行目标压缩/接触算例；
- 设计动态接触。

### G0

必须通过：

- 候选包可导入；
- blob 身份完整；
- 依赖图和接口清单存在；
- 表征算例可复现；
- 没有正式文件变化。

## P1：纯物理核

### 目标

建立与求解器、I/O、验证基础设施无关的局部力学函数。

### 工作

1. 实现显式拓扑和自由度映射；
2. 实现单边轴向材料的能量、试算力、最终拉力和耗散；
3. 实现离散弯曲能与力；
4. 实现摆球连接点运动学和力矩映射；
5. 实现 $SO(3)$ 指数映射、群乘法和角速度映射；
6. 实现质量、重力、浮力和明确启用的空气力接口；
7. 实现局部力—能量梯度、作用—反作用、客观性和被动性审计。

### G1

必须通过：

- 轴向能量梯度有限差分；
- 弯曲能量梯度有限差分；
- 刚体平移/旋转客观性；
- 内力合力与合矩闭合；
- 压缩状态轴力严格为零；
- 黏性与单边卸载总耗散非负；
- 姿态群运算保持单位性；
- 核心模块不导入 I/O、UI、分析或验证层。

**下一次 Codex 到此停止。**

## P2：无接触静态制备

### 进入条件

Pro 或用户明确要求继续，且 G1 已通过。

### 目标

直接求解 HF-v2 张力单边模型的定端静态平衡，不使用 `compression_regularization_scale`。

### 工作

1. 组装总势能和固定端点约束；
2. 选择一个主求解算法并冻结，不建立自动求解器瀑布；
3. 建立确定性多种子协议，种子集合在看到结果前冻结；
4. 独立复算力平衡和二阶稳定性；
5. 先运行解析可控的小系统，再运行三锚点中的一个无接触、正净空算例。

### G2

- 力残差通过冻结门；
- 单边轴力成立；
- 势能局部极小性有独立证据；
- 多种子选择规则没有使用目标结果调参；
- 网格加密的静态形状和反力呈收敛趋势。

## P3：静态硬接触

### 目标

把接触反力纳入静态方程，消除“无接触平衡后事后判负净空”的架构错误。

### 工作

1. 建立正式登记到逐接触约束的只读适配器；
2. 精确展开同支 `full_pairs`；
3. 精确展开 `partial_pairs` 的固定材料参数域；
4. 精确展开结点套筒和摆球套筒活动域；
5. 组装每项 $g_i$ 和 $J_{g_i}$；
6. 求解静态接触 KKT；
7. 独立审计原始、对偶、平衡、互补和二阶条件；
8. 非唯一最近点或零距离法向失败关闭。

### 运行顺序

先运行小型接触基准，再运行 HF-v2 的张力单边目标静态算例。旧 `alpha=1e-2` 只能作为 RC1 legacy 对照，不进入 HF-v2 模型参数。

### G3：Pro 裁决门

Codex 提交证据后停止。Pro 需要裁决：

- 接触登记是否与正式定义完全一致；
- KKT 与稳定性证据是否充分；
- HF-v2 静态接触模型是否允许进入动力学阶段。

## P4：平滑区间动力学

### 目标

在始终张紧、无接触的光滑区间实现统一隐式中点与群姿态推进。

### 工作

1. 实现单一 Newton/线搜索步骤；
2. 实现预冻结的步长拒绝和步长控制；
3. 实现保守、阻尼和规定支点功率账本；
4. 解析基准：自由刚体、单摆、小振幅耦合、轴向振子；
5. 时间步减半验证二阶收敛；
6. 与 RC1 在共同光滑模型域内比较，但不要求复制 RC1 数值误差。

### G4

- 二阶时间收敛；
- 保守能量误差随步长二阶下降；
- 被动系统无未解释正功；
- 姿态误差由群算法控制；
- Newton 失败不会触发静默换算法。

## P5：张紧—松弛活动集

### 目标

在每个接受步内直接满足单边张力，取代输出采样后的“负轴力—事件标签”补丁链。

### 工作

1. 实现半光滑活动集或等价互补求解；
2. 给出张紧、松弛和重新张紧的步内身份；
3. 建立一维绳段和小网络基准；
4. 验证动量、能量和耗散账本；
5. 做时间步和活动集稳定性研究。

### G5：Pro 裁决门

Pro 审查活动集算法是否可作为物理主链。未批准前不得接入正式程序。

## P6：动态硬接触

### 状态

`CLOSED`

### 开启前必须由 Pro 冻结

- 速度级或位置级互补形式；
- 冲量律；
- 恢复系数政策；
- 摩擦政策；
- 接触集合生成；
- 接触后能量与动量解释；
- 时间步与接触集加密门。

Codex 不得自行用 $e=0$、$e=1$、罚刚度或库默认值替代该裁决。

## P7：外围适配

### 目标

数值核心通过后，接入现有配置、公共 API、结果类型、HDF5、分析和 UI。

### 原则

- 适配器只转换数据，不复制物理；
- HF-v2 使用新 `model_id`；
- RC1 与 HF-v2 可并行选择；
- 不覆盖既有 RC1 结果格式；
- 旧状态词汇与新资格状态明确映射。

## P8：性能、三锚点和正式提升

### 工作

1. 三锚点的空间与时间加密；
2. RC1、FWD-CABLE、HF-v2 模型形态比较；
3. 性能剖析后再优化热点；
4. 不允许以牺牲模型清晰度换取微小性能收益；
5. 形成正式提升候选补丁。

### 最终门

只有用户明确授权，且 Pro 通过物理、数值和迁移审查后，才能修改 `02_模拟程序/**`。RC1 在新后端完成代表性验证前不得删除。
