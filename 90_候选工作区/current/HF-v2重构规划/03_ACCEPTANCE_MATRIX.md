# HF-v2 验收矩阵

## 1. 证据等级

所有阶段报告必须区分：

1. 源码与目录检查；
2. 单元实现测试；
3. 数值算法验证；
4. 模型间比较；
5. 物理验证；
6. 实验验证。

没有实验数据时，最高只能声明数值资格或条件性物理一致性，不能声明实验预测已经验证。

## 2. 预冻结尺度

每个目标运行前生成 `contracts/acceptance_manifest.json`，至少冻结：

- 特征长度 $L_*$；
- 特征时间 $T_*$；
- 特征速度 $V_*=L_*/T_*$；
- 特征力 $F_*$；
- 特征能量 $E_*=F_*L_*$；
- 网格层级；
- 时间步层级；
- 绝对与相对容差；
- 多种子集合；
- 接触候选集策略；
- 通过/失败判据。

看到目标结果后不得直接覆盖该清单。任何门槛变更必须生成新版本，并说明是数学修正、尺度修正还是结果驱动调参。

## 3. P1 纯物理核

| 项目 | 最低证据 |
|---|---|
| 轴向力—能量一致性 | 中心有限差分与解析梯度相对误差在步长收敛区间内下降，最终建议阈值不高于 `5e-7` |
| 弯曲力—能量一致性 | 同上；必须覆盖直杆、平面弯曲、三维弯曲和接近奇点但仍合法的状态 |
| 作用—反作用 | 内力合力与关于任意原点的合矩接近机器精度，使用尺度化阈值 |
| 客观性 | 刚体平移和共同旋转不改变内能；力按旋转协变 |
| 单边性 | 所有压缩段最终轴力为零，不能只在输出层截断 |
| 被动性 | 黏性耗散率和单边卸载附加耗散均非负 |
| 姿态群性质 | 连续群更新后 $R^{\mathsf T}R-I$ 与 $\det R-1$ 保持在舍入误差尺度 |

## 4. 静态 KKT

建议预冻结的初始绝对下限为：

- 原始穿透：不大于 `1e-10 m`；
- 对偶负值：不大于 `1e-10 N`；
- 力平衡：不大于 `max(1e-8 N, 1e-8 F_*)`；
- 互补：不大于 `max(1e-12 N*m, 1e-10 E_*)`。

这些是候选起点，不是不可修改的物理常数。修改必须发生在目标结果出现前，或由独立舍入/尺度分析证明。

静态通过还必须满足：

- 每个活动接触有可追踪身份；
- 最近点见证唯一且可微，或明确使用非光滑方法；
- 活动约束雅可比秩被审计；
- 至少有一个独立于主优化器的 KKT 复算；
- 二阶稳定性不能只看优化器退出码；
- 多种子选择依据势能、KKT 和稳定性，而不是依据接近预期轨迹。

## 5. 平滑动力学

| 项目 | 通过原则 |
|---|---|
| 时间阶 | 在解析或高精度基准的渐近区间，步长减半误差比接近二阶；建议至少大于 `3` |
| 保守能量 | 固定物理时窗内能量误差随步长减半呈二阶下降；不以一次小漂移替代阶数证据 |
| 被动耗散 | $\Delta E + D - W_{\mathrm{ext}}$ 随步长收敛，且不存在持续正的未解释功率 |
| 动量/角动量 | 在相应对称基准中随步长收敛；有外力时使用完整冲量平衡 |
| 姿态 | 不依赖每步强制归一化才能保持合法 |
| 非线性求解 | 记录残差、迭代数、拒绝步和最终失败；不得隐藏在 fallback 中 |

## 6. 单边张力活动集

必须覆盖：

- 始终张紧；
- 初始松弛；
- 单次松弛；
- 单次重新张紧；
- 多段同时切换；
- 近切触但不发生切换；
- 网格加密下事件/活动集稳定性。

通过要求：

- 每个接受步轴力非负；
- 活动集切换不依赖输出采样网格；
- 无伪能量注入；
- 时间步减半后切换时间和宏观轨迹收敛；
- 切触与真正穿越在算法层可区分，而不是事后状态标签修补。

## 7. 动态接触

P6 开启后至少验证：

- 非穿透；
- 法向冲量非负；
- 冲量—相对速度互补；
- 冲击前后动量平衡；
- 恢复系数合同；
- 接触耗散与数值耗散分离；
- 同时接触和接触集合退化；
- 时间步、接触候选集和网格加密；
- 无摩擦时切向冲量为零。

仅“没有崩溃”或“视觉上没有穿透”不构成通过。

## 8. RC1 对照

RC1 对照分三类：

1. **共同模型域**：始终张紧、无接触、相同材料和摆球参数；应比较收敛极限；
2. **模型身份不同**：RC1 双侧压缩正则与 HF-v2 张力单边；差异应被解释，不要求一致；
3. **RC1 超出物理域**：出现自穿透或依赖 guard 终止；HF-v2 不应复制该行为。

禁止把 RC1 单条轨迹作为 HF-v2 的绝对真值。

## 9. 三锚点门

`4:3`、`3:2`、`2:1` 只有在单元、静态和小型动力学基准通过后才能运行。每个锚点至少要求：

- 三层空间网格；
- 三层时间步；
- 力、能量、活动集和接触证据；
- 公共摆球观测量；
- 模型身份差异说明；
- 不以目标频率比接近程度作为数值正确性标准。

## 10. 架构验收

- 新核心不存在对 UI、I/O、分析和正式验证模块的反向依赖；
- 单个核心文件原则上不超过约 `800` 行；超过时必须说明为何不能按物理职责拆分；
- 单个公共函数原则上只承担一个方程或算法职责；
- `solver` 不包含哈希、绘图、HDF5、CPU 核检测或报告生成；
- 不存在自动求解器瀑布；
- 不存在为了通过测试而静默放宽物理域；
- 每个模型开关都会改变明确的模型身份或配置合同。

## 11. 性能验收

性能优化只能发生在数值正确性之后。要求：

- 先有剖析数据；
- 优化前后轨迹和资格证据等价；
- 不通过减少守卫、降低精度或跳过 KKT 获得加速；
- 大数组分配、稀疏装配和局部接触查询有独立基准；
- 性能结果绑定硬件、线程数、Python/NumPy/SciPy 版本和配置。
