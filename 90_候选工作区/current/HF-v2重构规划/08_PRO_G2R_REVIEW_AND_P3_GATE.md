## 2. 完整静态组装身份

G2R 保留兼容字段名 `layout_token`，但将其语义统一为坐标解释和完整静态物理组装的单一 SHA-256 身份。源码实际绑定：

- 节点 ID、节点种类、唯一摆球连接节点和自由节点顺序；
- 材料段 ID、支路、端点、材料坐标和段顺序；
- 全部自由节点、摆球平移和旋转切片及广义维数；
- 参考摆球姿态、右乘 `SO(3)` 指数坐标约定和旋转图域上限；
- 规定节点身份和规定支点位置；
- 支路材料、显式及集总节点质量和排液体积；
- 摆球质量、体积、惯量和连接臂；
- 重力、流体密度和浮力开关。

序列化使用固定 schema、键排序、固定分隔符和 `allow_nan=False`。坐标入口仍只接受携带完全相同 token 的 `StaticCoordinates`。

四类真实跨组装反例分别改变参考摆球姿态、摆球连接/规定节点身份、支点位置和重力。每一例均产生不同 token，且原组装坐标进入变体组装时以 `ValueError` 失败关闭。前次指出的“同形数组可跨物理组装静默使用”问题已经关闭。

当前 token 对 P2 无接触静力学是完备的。P3 若引入接触约束，必须升级模型/约束身份，并把接触登记版本、逐接触对身份、所需中心距和接触政策纳入新的接触组装身份；不得把 P2 token 误写成接触模型身份。

## 3. BFGS 参数和运行时附录

生产静态求解路径仍只有一次 SciPy BFGS 调用。实际 `options` 显式包含：

```text
gtol = 1e-9
maxiter = 2500
xrtol = 0
norm = inf
disp = false
c1 = 1e-4
c2 = 0.9
```

单元测试通过替换 `minimize` 捕获实际调用映射；生产入口将 `Unknown solver options` 的 `OptimizeWarning` 提升为异常，不允许不兼容运行时静默忽略参数。

SciPy 1.11.4 的 BFGS 文档未列出 `c1`、`c2`，而 SciPy 1.12.0 文档已经明确列出两项选项。G2R 原协议后的第一次 SciPy 1.11.4 尝试因未知选项警告整体作废；随后在第一次有效重跑前提交 G2R-A1：最低 SciPy 修正为 1.12，绑定第一次有效证据环境为 CPython 3.12.3、NumPy 2.5.2、SciPy 1.18.1，并保持全部物理参数、数值门和等价容差不变。

这不是完整无偏预注册链，因为运行时附录发生在一次无效尝试之后；但触发原因是可直接复核的 API 不支持，作废结果没有进入工件，也没有引起阈值、种子、网格或物理参数变化。该时间顺序已充分披露，可以作为独立 G2R 修正协议接受。

证据生成器还检查绑定运行时的 `_minimize_bfgs` 签名实际包含 `c1` 和 `c2`。该私有符号只用于审计，不进入生产静态求解器；未来 SciPy 结构变化会使证据失败关闭，而不是改变物理结果。

## 4. 历史 G2 治理与等价性

G2R 没有覆盖历史 `G2_REPORT.md`、`g2_metrics.json`、G2 冻结协议或 G2 验收清单。其 SHA-256 在新证据中逐项核对。

原 G2 的两项后验变化已经版本化披露：

1. 预冻结模块依赖清单后来扩展了 `physical_core` 对状态和拓扑合同的允许依赖；
2. 第一次未提交 G2 试算后，闭合审计才区分自由平衡残差与作用—反作用恒等式残差。

修正后的闭合定义在数学上正确，但历史 G2 不再被描述为完整无偏预注册结果。G2R 在单独冻结的合同下重算，并明确把历史 G2 只作为修正后可信、不可变的比较工件。

三个网格保持同一选中种子。新旧结果的总势能、宏观形状、全部段张力、两支点反力和最小非规范 Hessian 特征值差值均为精确浮点零，说明身份元数据、显式线搜索参数和新增审计没有改变已观察的静态解。

## 5. 完整中心线和无量纲诊断

三条支路均在 129 个公共归一化材料坐标点上分段线性重采样。4→8 与 2→4 的最大同材料点位差比为：

- 左上支：约 `0.2497244`；
- 右上支：约 `0.2497244`；
- 下支：约 `0.2489830`。

每条支路的细网格差值均严格小于粗网格差值，并明显低于既有上限 `0.95`。该结果关闭了先前只比较结点、附件和摆球而遗漏完整绳形的证据缺口。

新增逐段工程应变、当前长度中的伸长占比和当前长/静长比。三网格范围稳定在约 1% 伸长，全部有限；两项代数恒等式最大误差为 `1.7347e-18`。这些量只作域和网格客观诊断，没有替换或放宽原绝对伸长、张力、段长和净空门。

## 6. 数值结果复核边界

G2R 继承的解析竖直系统、总势能—解析广义力、三网格 Y 形平衡、三个确定性种子、单边域、净空、反力闭合和二阶稳定性仍全部通过。关键静态结果没有因 G2R 改变。

2 段和 8 段选中候选仍记录 BFGS 状态 2，4 段为状态 0。状态 2 没有被当作成功，也没有触发重启、替代求解器或容差放宽；独立力残差、正域裕量和 Hessian 门有明显余量。因此它不阻断当前条件性静力资格，但仍是求解器稳健性限制。正式提升前应增加受支持 SciPy 版本矩阵和更广静态算例，而不是隐藏状态 2。

GitHub 当前没有绑定远端状态检查。`72 passed`、Ruff、`compileall`、JSON、Pandoc 和逐字节证据检查属于提交携带的本地证据；本次复审没有把它们写成 GitHub Actions 的独立 CI 背书。我独立核对了提交顺序、源码、合同、关键公式、关键指标和官方 SciPy 选项文档，但没有在连接器环境中重新执行整套本地测试。

## 7. 是否属于“补丁叠补丁”

G2R 没有新增物理力、罚势、求解器 fallback、随机重启、容差放宽或特殊结果分支。它完成的是：

- 用一个字段完备的身份合同替换不完整 token 语义；
- 把已经冻结但未传入的 BFGS 参数直接送入原唯一求解器；
- 将协议偏离版本化，而不是追溯改写历史；
- 补齐完整中心线和无量纲解后审计。

因此本轮不是 RC1 式的外围补丁链。G2R 完成后，P2 静态底层应冻结；P3 不得再修改 P2 的轴向、弯曲、刚体、质量或无接触静态方程，除非出现可复现的独立反例并重新升级模型身份。

## 8. P3 准入边界

只有用户再次明确要求继续时，Codex 才可执行 P3 静态无摩擦刚性单边接触，并必须在任何目标接触结果前冻结：

1. HF-v2 接触模型和接触组装身份；
2. 正式只读接触登记到逐约束集合的精确映射；
3. 每项接触的参数域、最近点见证、间隙、法向和雅可比；
4. 非唯一、零距离、塌缩段和活动集退化的失败关闭政策；
5. 唯一主求解算法、多种子、KKT、互补和二阶稳定性门；
6. 小型解析/高精度接触基准；
7. 首个目标静态接触算例和停止规则。

P3 不得直接复制已退出工作树的旧 `hard_contact_candidate`，不得导入旧 RC1 guard/压缩扫描结果作为新模型证据。可以按需读取正式 RC1 的接触登记定义和 Git 历史中的旧候选原理，但必须在 HF-v2 当前拓扑、组装和身份合同上重新实现并重新验证。

P3 只开放静态无摩擦法向接触。摩擦、恢复系数、动态互补、冲量和接触后时间推进继续关闭。完成 G3 后必须停止并交回 Pro。
