# Y 形摆：三锚点高保真初始窗数值资格

## 1. 结论

本目录把上一轮 `4:3`、`3:2`、`2:1` 三个锚点提升到正式高保真空间层级，并在同一份预冻结资格规格下完成：

- 三锚点各 3 个空间层级的准备态审计；
- 三锚点各 3 个空间层级、`0.12 s` 初始窗的动态 Cauchy 诊断；
- `3:2` 生产层的独立单束证书尝试。

三个锚点的高保真数值资格均为 **NO-GO**，不能转化为装置尺寸、加工公差或真实频率比建议：

1. 三个锚点的正式 Cauchy 门均未整体通过。`4:3` 和 `3:2` 的失败指标是最大杆速度，`2:1` 的失败指标是摆球角速度 RMS。
2. `4:3` 的轴向压缩在三层准备态和三层动态结果中都存在，且细化后没有消失；它属于双侧材料律下的准备态和后续响应，不是上一轮 1--2 单元网格的偶然假象。
3. `3:2` 在三个正式空间层级的 `0--0.12 s` 内始终严格受拉；上一轮 2 单元结果在 `t=0.025 s` 出现的负轴力没有复现。证据指向低于正式层级的空间离散或其他数值设置，但本轮没有通过单因素消融把原因唯一归给网格。
4. 三个锚点的所有准备态都因 `ROD_SELF_CLEARANCE` 低于预冻结的最小归一化裕量 `3e-4` 而失败。生产层最小值约为 `1.09e-4`、`8.38e-5` 和 `3.60e-5`。
5. 最终证据复核发现，历史空间运行的外层源码探针把已经位于 `src/` 的路径又拼接了一次 `src/`，所以原始结果中的 `e3b0...` 是空 Python 源码树哈希。当前正式源码哈希 `1c0...` 与冻结计划一致，探针也已修复，但这不能倒推证明三次历史空间研究的两个运行端点。汇总状态因此明确增加 `SOURCE_ENDPOINT_PROBE_INVALID`，没有把原始 `formal_source_stable=true` 继续当成有效证据。

本轮时窗只有 `0.12 s`，用于正式后端的初始数值资格，不覆盖上一轮约 `9--15 s` 的模态分析窗。因此，外部位置指标在短窗内呈现良好收缩，也不能证明长期频率、相位、闭合或装置轨迹收敛。

## 2. 预冻结输入与空间层级

三个锚点继续使用上一轮三锚点模型阶梯的几何、材料、释放状态和共享输入映射。每个锚点的柔索--高保真共享输入审计仍为 53 项全部通过。

生产配置固定为：

- 模型：`HF-DISCRETE-ROD-RIGID-BOB-1.0`；
- 时窗：`0.12 s`；
- 输出步长和生产层最大步长：`7.8125e-6 s`；
- 积分器：Radau；
- 配置档位：`production`；
- 纵波解析：启用；
- 相对容差：`1e-8`；
- 位置、四元数绝对容差：`1e-10`；
- 速度、角速度绝对容差：`1e-9`。

正式验证代码从生产层生成以下三层空间序列：

| 层级 | 上支 A 单元 | 上支 B 单元 | 下支单元 | 角色 |
|---|---:|---:|---:|---|
| 粗层 | 6 | 6 | 8 | 正式验证中的粗层趋势；允许低于单次生产下限 |
| 中层 | 12 | 12 | 16 | 正式验证中的粗层趋势；允许低于单次生产下限 |
| 细层 | 24 | 24 | 32 | 生产层 |

候选脚本直接调用正式代码中的空间配置、材料坐标比较、Cauchy 门和事件稳定性逻辑。它没有重写另一个“近似验证器”，也没有在看到结果后放宽阈值。

源码身份需要单独说明：输入冻结阶段、修复后重跑的准备态诊断和代表性证书尝试都记录了正式源码哈希 `1c0b8a6f...`。但是，9 个历史空间运行的候选包装器错误地对不存在的 `src/src/ypendulum` 求哈希，得到空树哈希 `e3b0c442...`。配置、规格、候选脚本和运行环境的起止检查仍有效，27 个大工件也仍与原候选清单一致；只有“历史空间运行端点正式源码稳定”这一项被降为未直接验证。保留原始空间 JSON 不改写，`results/run_summary.json` 以 `identity_checks_as_recorded`、`effective_identity_checks` 和 `source_provenance_assessment` 同时呈现原记录与纠正后的判定。

## 3. 准备态诊断

下表只比较 `t=0` 的独立参考核重算结果，不是动态收敛证据。

| 锚点 | 粗层最小有符号轴力 / N | 中层 / N | 细层 / N | 细层最小归一化守卫裕量 | 初态判定 |
|---|---:|---:|---:|---:|---|
| `4:3` | -0.004411 | -0.004694 | -0.004772 | 1.091e-4 | 下支存在压缩；守卫门失败 |
| `3:2` | +0.003468 | +0.003158 | +0.003080 | 8.384e-5 | 全支严格受拉；守卫门失败 |
| `2:1` | +0.007325 | +0.007001 | +0.006920 | 3.601e-5 | 全支严格受拉；守卫门失败 |

`4:3` 的负轴力位于下支。非正轴力单元数随网格从 2 个增加到 3 个和 5 个，但物质区间保持在下支靠近摆球的一端；最小值也随细化趋近约 `-4.8 mN`。这排除了“只在 1--2 单元预览网格出现”的解释。

这里还要区分两个不同门槛：正式准备器所说的 `guards_valid=true` 只表示原始机器/几何守卫没有穿越零；本轮资格规格额外要求每个守卫具有大于 `3e-4` 的归一化正裕量。三锚点均满足前者、失败于后者，二者不能混写成同一个 PASS。

## 4. 三层动态空间诊断

### 4.1 整体门禁

| 锚点 | 中层到细层失败指标 | 细层差值 | 预冻结阈值 | 事件稳定性 | 空间诊断 |
|---|---|---:|---:|---|---|
| `4:3` | 最大杆速度 | 0.434954 m/s | 0.300000 m/s | 失败 | `NOT_DEMONSTRATED` |
| `3:2` | 最大杆速度 | 0.308234 m/s | 0.300000 m/s | 通过 | `NOT_DEMONSTRATED` |
| `2:1` | 摆球角速度 RMS | 0.021955 rad/s | 0.020000 rad/s | 通过 | `NOT_DEMONSTRATED` |

三个失败指标都随细化下降，分别具有正的表观二进制阶数；但“正在收缩”不等于“已经低于预冻结阈值”。结果文件保存了每个范数的表观阶数和几何尾差估计。由于输入只是两组非负差值范数，没有带符号的场值，本轮不伪造 Richardson 外推场值。

`4:3` 的事件稳定性失败不是因为事件时间相差超过 `2 ms`，而是各支张力--压缩物质区间的事件重数随网格显著变化。例如上支 A 的压缩转拉伸事件数为 5、9、18；下支为 2、3、5。正式事件门按失败关闭。

### 4.2 通过的代表性差值

下表给出中层到细层的代表性 RMS 差值。位置统一换算为毫米，轴力保持牛顿。

| 锚点 | 摆球位置 / mm | 结点位置 / mm | 杆位置 / mm | 杆有符号轴力 / N |
|---|---:|---:|---:|---:|
| `4:3` | 0.002687 | 0.023544 | 0.100918 | 0.003730 |
| `3:2` | 0.002784 | 0.013409 | 0.102376 | 0.003558 |
| `2:1` | 0.004015 | 0.103814 | 0.171195 | 0.006369 |

这些指标分别低于各自阈值并满足收缩要求，但整体门禁是所有注册指标和事件的合取，不能挑选外部位置结果后把 27/28 写成 PASS。

## 5. 轴力来源诊断

### 5.1 `4:3`

三层动态最小有符号轴力分别为 `-0.03572 N`、`-0.03669 N` 和 `-0.03698 N`。生产层在初态已有下支压缩，随后上下支还发生多次张力--压缩切换。当前证据把来源定位到双侧轴向材料律下的稳定准备态及其动态传播；要判断这种双侧响应是否对应真实绳索，必须另做压缩正则化和仅受拉极限研究。

### 5.2 `3:2`

三层动态最小有符号轴力与准备态相同，分别为 `+0.003468 N`、`+0.003158 N` 和 `+0.003080 N`，没有轴力事件。上一轮 2 单元细网格的 `-0.00158 N` 样本发生在本轮时窗内，却没有在 6、12、24 单元层级复现。因为本轮还同时切换到生产积分配置，最严谨的结论是“低层级数值设置相关”，而不是“已唯一证明为网格误差”。

### 5.3 `2:1`

三层动态最小有符号轴力为 `+0.007325 N`、`+0.007001 N` 和 `+0.006920 N`，没有轴力事件。它仍因守卫裕量和角速度空间指标失败，不能用“始终受拉”替代整体资格。

## 6. `3:2` 代表性单束证书尝试

生产层原始积分已完成：

- 接受步数：15,366；
- 积分运行时间：约 `372.68 s`；
- 最小有符号轴力：`+0.003080 N`；
- 最大绝对归一化能量平衡残差：`1.94e-10`；
- 最大四元数范数误差：`5.11e-15`。

抽样输出已经证明资格不能通过：`ROD_SELF_CLEARANCE` 的最小归一化裕量为 `8.384e-5`，低于 `3e-4`；15,361 个输出样本中有 12,261 个不超过门槛，持续到约 `0.09578 s`。

完整连续接受步证书最终**没有取得**。正式实现会对每个接受步重算独立 RHS、动力学缺陷、展示网格绑定和 11 个守卫组件，即使抽样前置门已经失败也不会提前返回。本次进程持续到约 10,000 秒墙钟后以退出码 143（SIGTERM）结束；没有 OOM 或正式异常输出，结束时点与执行会话外部时限一致，因此记录为 `EXTERNAL_EXECUTION_SESSION_LIMIT_INFERRED`，而不是正式证书返回的 FAIL。

原子目标目录和 `hf_single_bundle_certificate.json` 均未出现。完整积分检查点、暂存 HDF5、配置、规格和诊断均已保留并重新哈希，共 8 个文件、约 277 MB。`results/certificate_attempt.json` 固化了命令、时间、退出状态、身份和工件哈希。当前证据可以确认“抽样资格必败”和“完整证书未返回”，不能声称连续证书通过，也不能伪造一个返回的连续证书失败状态。

## 8. 文件与复现

主要提交文件：

- `qualification_plan.json`：输入、正式源、正式规格、三层网格和资源身份；
- `shared_input_audits.json`：三锚点各 53 项共享输入审计；
- `configs/*.yaml`：三个生产层配置；
- `results/initial_level_diagnostics.json`：三锚点三层准备态；
- `results/spatial/*.json`：三锚点动态比较、门禁、事件和工件身份；
- `results/certificate_attempt.json`：不完整证书尝试的退出状态、身份和保留工件哈希；
- `results/run_summary.json`：最终紧凑汇总；
- `MANIFEST.sha256`：提交交付物清单。

`generated/` 保存 HDF5、单次运行和证书暂存，已被 Git 忽略。第一次 `4:3` 数值计算在写摘要时因 `numpy.bool_` 严格 JSON 序列化失败；其 272 MiB 完整工件保留在 `generated/orphaned_after_serialization/4to3/`，没有混入标准结果。修复后使用同一正式输入重跑，并增加回归测试。

三个 `results/spatial/*.json` 是历史运行的原始返回记录，其中保留了错误空树哈希，不能脱离 `results/run_summary.json` 的来源纠正说明单独解读。修复后的脚本会对真实 `src/ypendulum` 求哈希；测试同时要求该路径存在且哈希等于冻结计划，防止相同路径错误再次静默通过。

在本目录运行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python build_qualification_configs.py
.venv/bin/python initial_level_diagnostics.py
.venv/bin/python run_spatial_diagnostic.py 4to3
.venv/bin/python run_spatial_diagnostic.py 3to2
.venv/bin/python run_spatial_diagnostic.py 2to1
.venv/bin/python -m pytest -q tests
.venv/bin/python summarize_qualification.py
sha256sum -c MANIFEST.inputs.sha256
sha256sum -c MANIFEST.sha256
```

三个空间诊断在门禁未通过时按设计返回退出码 2，但仍原子写出完整结果和工件；复现脚本不能把退出码 2 当作 PASS，也不能因此删除失败证据。

## 9. 下一步与停止条件

1. 先定位三锚点初态 `ROD_SELF_CLEARANCE` 裕量不足来自共享几何、接头/摆球套筒排除区定义，还是正式守卫尺度；不得在看过结果后直接放宽 `3e-4`。
2. 对 `4:3` 执行预先定义的压缩正则化和仅受拉极限研究，比较准备态、事件物质区间、能量账和外部轨迹，不能把双侧杆与真实绳索直接等同。
3. 守卫域满足后，再补完整时间细化和双积分器矩阵；局部杆速度与摆球角速度仍需通过冻结阈值。
4. 数值资格满足后，才进入可测输入、校准集、盲验证集和装置级不确定度。

在这些门禁完成前，三个锚点都不得被写成真实装置最优频率比、尺寸或稳定图样预测。
