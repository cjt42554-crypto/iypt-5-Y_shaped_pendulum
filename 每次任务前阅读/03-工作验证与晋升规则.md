# 03｜工作、验证与晋升规则

## 1. 默认工作流程

1. 读取接力控制区和当前任务入口。
2. 现场确认 Git 身份、**main**、HEAD、工作树及已有修改，并核对本地/远端没有其他分支。
3. 在 **未提交修改/当前任务/** 内确定本次候选、管理和审查输出位置。
4. 修改前记录目标、来源和预期晋升映射。
5. 实施最小范围修改，保留失败证据和未证明事项。
6. 按风险执行验证，并把命令、环境、提交口径、结果和未运行项写入 **验证记录.md**。
7. 更新当前状态、变更映射、验收清单和修改记录。
8. 直接在 **main** 形成范围单一的 commit 并 push，供下一位协作者从 GitHub 接力。

## 2. “未提交修改”的准确含义

该名称只表示内容尚未通过晋升流程进入成熟基线。工作区内可以存在：

- 已 commit、已 push 的阶段实现；
- 正在审查的候选提交；
- 可复现的机器证据和失败日志；
- 尚未接受的文档、数据、程序或实验设计。

不得用 Git 工作树是否 clean 来判断内容是否成熟。Git 提交解决协作和追踪，晋升解决质量与
权威边界；两者是不同维度。

## 3. 验证记录最低要求

每项重要结果至少记录：

- 仓库、分支、完整提交哈希和工作树状态；
- 被验证的确切路径与输入身份；
- 命令、运行环境、退出码和测试计数；
- 输出或日志的位置与必要哈希；
- PASS、FAIL、SKIPPED、UNKNOWN 或 NOT_RUN；
- 结果能证明什么、不能证明什么。

历史日志若含旧绝对路径可以保留，但必须标记历史提交。路径迁移、源码变化、阈值变化或输入
变化后，不能把旧 PASS 直接提升为当前 PASS。

## 4. 晋升前置条件

候选只有同时满足以下条件，才可以请求晋升：

- 候选来源提交已冻结并已 push；
- [变更映射.md](../未提交修改/当前任务/管理/变更映射.md) 精确列出每个目标路径；
- [验收清单.md](../未提交修改/当前任务/管理/验收清单.md) 的适用项全部通过；
- 相关测试、数值检查、文档检查和独立审查绑定同一候选提交；
- 所有 FAIL、UNKNOWN、未证明事项和科学声明上限已显式处理；
- 有可恢复的基线身份和清楚的回滚点；
- 用户明确批准本次具体晋升范围。

目录名、版本号、README 自述、manifest 字段、单次成功运行或视觉相似都不能替代这些条件。

## 5. 晋升操作

1. 从冻结候选生成面向根目录 01/02/03 的精确差异，不整体覆盖。
2. 先复核成熟基线当前身份，确认没有并行漂移。
3. 以独立晋升提交应用已批准差异。
4. 在晋升后的提交上重新运行适用验收，不能只引用候选提交结果。
5. 更新三棵成熟目录的新身份、当前状态、修改记录和发布/回滚说明。
6. push 晋升提交；在确认成功前保留工作区来源与证据。
7. 当前任务完成后，将其改名或迁入工作区历史任务目录；不得仅删除接力上下文。

## 6. 科学与能力等级

能力声明按以下层级分别取证，不允许跨级推断：

~~~text
MODEL_CONSISTENT
  → CODE_VERIFIED
  → NUMERICALLY_QUALIFIED
  → EXPERIMENTALLY_VALIDATED
  → PREDICTIVE
~~~

- 测试全绿主要支持代码层，不自动支持数值资格。
- 数值收敛和求解器交叉检查不自动说明物理模型符合实验。
- 使用校准数据拟合不等于盲预测。
- 完整运行、完整几何或独立留出验证优先于相邻帧、单个时间点或挑选案例。
- 对仅受拉分支必须持续检查张力；出现负张力时，该等式约束分支失效，必须进入明确的事件/
  活跃集模型或停止该分支。

## 7. Git 安全边界

- 阶段成果正常 commit/push；不把工作区当成长期未提交缓存。
- 唯一允许创建、签出和推送的分支是 **main**；不得新建功能、审查、交接或晋升分支。
- 文件夹结构承担传统分支的隔离职责：开发留在 **未提交修改/**，成熟内容只通过明确晋升写入
  根目录 01/02/03。
- 发现旧分支时，必须先核对独有提交和工作树，把仍需保留的成果接管到 **main**，再删除旧分支。
- 不强制推送，不重写他人历史，不删除不明修改，不用破坏性清理制造干净状态。
- 大规模重命名优先保留 Git 可识别的来源关系。
- 提交前检查成熟基线是否只读、根目录是否只保留治理/兼容例外、链接是否可解析。
